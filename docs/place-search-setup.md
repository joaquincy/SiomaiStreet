# Worldwide place search

The homepage has visible **Search any place / Our stores** controls. Worldwide search is shown first; the branch-name filter remains under Our stores. Search runs on explicit submission, returns up to five Geoapify candidates, and requires a visitor to choose one. Adding a city/country helps disambiguate business names; coverage is not exhaustive. Choosing a result opens the map and centers the search point.

Choosing a result clears branch text/region filters, cancels pending device location, sorts published branch pins by straight-line distance, and displays the selected origin. With the optional map open, a blue search-point marker is distinct from numbered store pins. Searches with no published branch within 50 km say so explicitly; results do not imply a Siomai Street branch exists there. Unpinned branches remain in the directory without distance estimates.

## Activate

1. Create an account/project at https://myprojects.geoapify.com/ and obtain an API key. Review its current plan and terms; the geocoding documentation currently offers a free key without a credit card: https://apidocs.geoapify.com/docs/geocoding/ . No account was created for you.
2. Add `GEOAPIFY_API_KEY=your_key` to your local `.env` and add `GEOAPIFY_API_KEY` in Vercel's environment variables for the desired environment. This is a **server variable**, never `VITE_GEOAPIFY_API_KEY`. Do not paste it into chat or commit it. Configure provider restrictions appropriate to server-side requests; browser-referrer restrictions can break a backend proxy.
3. Reuse your existing `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `APPLICATION_RATE_SECRET` and the `consume_application_rate` RPC from the existing application-security migration. No new database/table/migration is needed. Missing abuse protection fails closed for external searches; the branch directory remains usable.
4. Restart local Node; commit the code and redeploy Vercel after configuring its key. Do not commit `.env`.
5. Test a Philippine city, a full overseas address, a named business with city/country, nonsense input and multiple similarly named places. Confirm the chosen coordinates before treating results as accurate. Test a location far from all branches, Clear search area, keyboard access and mobile view. Publish actual branch coordinates before expecting useful nearest-store distances.

## Controls and limits

- POST `/api/place-search` keeps search text out of the endpoint URL. No search queries, credentials or raw provider errors are logged by this handler. Infrastructure/provider retention is separate; review their settings and policies.
- Existing shared rate-limiter RPC: 20 search attempts per client/hour; 80 provider requests/hour across this app and all Vercel instances sharing the same project/secret. Other apps/keys can consume the same provider quota independently. Set provider budget controls too; rate limits do not guarantee a provider bill or uptime.
- Fixed provider URL, validated query (3–180 characters), at most five candidates, 8-second provider timeout, 128 KiB provider-response cap, four in-flight unique searches per process. Per-process hashed cache keys and maximum 100 result entries for five minutes; repeated simultaneous queries coalesce. No persistence of queries in Supabase.
- No autocomplete traffic, added SDK or package. User edits/closure/unmount cancel client fetches and ignore stale responses; already-started server requests may finish within the bounded provider timeout.
- Provider outages, quota exhaustion, invalid coordinates and no matches have recoverable messages. Ordinary branch search and external directions remain usable.
- Geoapify/OSM attribution appears with search results. Privacy notice updated. Public Nominatim is not used.
